# Report outline

The final report is half the deliverable and is graded on academic quality.
One file per chapter in `docs/`, written in parallel with the code, never left
to the end. Figures and tables come from `figures/`, generated by code.

| File | Chapter | Content |
|------|---------|---------|
| `01_introduction.md` | 1. Introduction | Problem, why feature selection matters in high dimensions, what this project delivers, contributions list. |
| `02_related_work.md` | 2. Related Work | Filter / embedded / wrapper taxonomy, Higher Criticism, prior comparative studies on gene expression. |
| `03_data.md` | 3. Data | SCAN-B: shape, targets (PAM50, ER, survival), class imbalance, preprocessing. Second dataset described the same way. |
| `04_methodology.md` | 4. Methodology | Selection methods, evaluation protocol (stratified CV, selection inside the fold), metrics, baselines including random selection. |
| `05_implementation.md` | 5. Software and Implementation | The `featsel` package: architecture, config-driven runs, selector interface, the parallel infrastructure and how it is measured. This chapter is where task 3 lives. |
| `06_results.md` | 6. Results | Comparison tables and figures across methods, targets and datasets, including runtime and selected-feature counts. |
| `07_discussion.md` | 7. Discussion | What the numbers mean, which methods win where, scaling behaviour, threats to validity, limitations. |
| `08_conclusion.md` | 8. Conclusion | What was built, what was learned, future work. |
| `09_references.md` | References | Consistent citation style throughout. |

Rules:

- Write the chapter as soon as the matching code produces output. A chapter
  written from memory weeks later is slower and worse.
- Every number in the report comes from a committed results file, never
  retyped by hand.
- Reproducibility statement in chapter 5: seeds, environment, how to re-run.
